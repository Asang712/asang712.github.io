# 实战 OpenCV：造一个「镜头运动分析器」，还能一键打包成桌面应用

> 关键词：OpenCV、LK 光流、RANSAC、卡尔曼滤波、Tkinter、PyInstaller

## 前言

上一篇文章我介绍了一个基于稀疏光流的镜头运动分析器雏形：给一段视频，它能实时判断镜头是**静止、横向移动、纵向移动还是抖动**，画出特征点轨迹和平均运动箭头，输出 CSV 日志并自动标记剧烈抖动片段。

但雏形离"能用"还差几步：画面里有个人走过，静止镜头就被误判成移动；换个 4K 视频阈值全失效；匀速起步的运镜被误判成抖动……这篇文章记录我把它**从"能跑"打磨到"可交付"**的三轮优化，以及最后打包成双击即用的桌面应用的全过程。

仓库地址：https://github.com/Asang712/OpenCV_basic_project

## 二、整体架构

经过拆分，项目现在是五个职责单一的模块：

```text
video_motion_analyzer.py  命令行入口：参数解析 + 主循环
gui.py                    Tkinter 桌面 GUI：参数面板 + 实时预览
analyzer.py               核心算法：光流 → RANSAC → 卡尔曼 → 分类
io_utils.py               视频输入：后台线程读帧的 VideoStream
viz.py                    可视化：中文渲染 + HUD 叠加
```

数据流一条直线：

```text
视频帧 → 灰度/缩放/CLAHE → Shi-Tomasi 角点 → LK 金字塔光流
     → 边缘区域采样 → 仿射模型 + RANSAC → 卡尔曼平滑
     → 分类(静止/横向/纵向/抖动) → 可视化 + CSV 日志
```

## 三、三个最关键的工程决策

### 1. 用 RANSAC 把"镜头动"和"物体动"分开

最初版本对所有跟踪点的位移求平均。问题很快暴露：**一辆车驶过画面，静止镜头就被带偏成"移动"**。

解法是用 `cv2.estimateAffinePartial2D` 拟合部分仿射模型，RANSAC 自动找最大一致集——内点代表背景整体运动（镜头），外点是运动前景：

```python
M, inliers = cv2.estimateAffinePartial2D(
    old_pts, new_pts, method=cv2.RANSAC,
    ransacReprojThreshold=3.0, maxIters=2000, confidence=0.99)
```

但 RANSAC 有个坑：**当前景物体足够大时，"最大一致集"可能是前景本身**。所以加了一道保险——内点占比低于 30% 就认为估计不可靠，直接复用上一帧向量，避免误报：

```python
inlier_ratio = mask.sum() / len(old_pts)
if mask.sum() >= 10 and inlier_ratio >= 0.3:
    return np.array([M[0, 2], M[1, 2]])  # 取仿射平移量
return None  # 不可靠，调用方复用旧向量
```

### 2. 只让"画面边缘"参与镜头估计

更进一步的洞察：前景物体（人、车）通常占据画面**中心**，背景（墙、天空、地面）在边缘。所以估计镜头运动时，只用外圈 20% 区域的特征点：

```python
b = int(min(h, w) * 0.2)
border_mask = ((old_pts[:,0] < b) | (old_pts[:,0] >= w-b) |
               (old_pts[:,1] < b) | (old_pts[:,1] >= h-b))
```

边缘点不足时回退到全部点。这一招和 RANSAC 是双重保险：边缘采样减少外点来源，RANSAC 兜底残余干扰。

### 3. 卡尔曼滤波 + "测量残差"重新定义抖动

最初用滑动窗口的方差判断抖动，问题有两个：窗口带来固定延迟（状态切换慢半拍），且**匀速起步的运镜**在窗口里波动很大，被误判成抖动。

换成卡尔曼滤波后，抖动有了更优雅的定义——**测量残差（innovation）**：

```python
y = measurement - H @ x   # 预测值与实测值的差
jitter = ||y||            # 残差越大 = 运动越不符合平滑预期 = 抖
```

平滑的运镜加速时，卡尔曼的常加速度模型能跟上，残差小；真正的手抖方向来回乱变，模型跟不上，残差大。这一下解决了"起步误报抖动"的顽疾，同时滑动窗口的固定延迟也消失了。

## 四、容易被忽略但救命的细节

- **阈值分辨率归一化**：阈值单位是"px/帧"，同一段物理运动在 4K 视频里像素位移是 720p 的 4 倍。所有阈值乘 `scale = 长边/720`，一套参数通吃所有分辨率。
- **跟踪降分辨率**：光流跑在缩到 640 宽的灰度图上，提速约 33%，而分类结果不变（因为阈值按跟踪分辨率归一化）。
- **CLAHE 光照归一化**：曝光突变会违反 LK 的亮度恒定假设，先过一遍 CLAHE 让光流稳很多。
- **中文渲染**：`cv2.putText` 不支持中文，用 Pillow 画文字，内置跨平台字体候选列表，找不到自动降级英文。
- **CSV 用 utf-8-sig**：带 BOM 头，Excel 双击打开不乱码。

## 五、从脚本到产品：桌面 GUI + 一键打包

写个 Tkinter 界面（Python 内置，零额外依赖）：左边参数面板实时可调全部阈值，右边视频预览叠加特征点和运动箭头，下方实时统计各状态占比。

然后用 PyInstaller 打成单文件：

```bash
./build.sh   # 产物: dist/MotionAnalyzer (~87MB)
```

接收方无需装 Python，双击即用。两点注意：

1. **打包用 `opencv-python-headless`** 替代 `opencv-python`，可再瘦一圈（无 GUI 依赖，本项目的窗口全走 Tkinter）。
2. **PyInstaller 不能交叉编译**：Linux 上打的包只能跑 Linux，Windows/macOS 需在对应系统重新执行 `build.sh`。

## 六、测试：合成视频做 ground truth

纯单元测试测不了"分类准不准"，所以写了个合成视频测试：用 OpenCV 画圆形特征点 + 高斯模糊，生成已知运动的帧序列（静止/右移/下移/抖动），断言收敛后的主导状态与 ground truth 一致。18 个用例全绿，改算法不再靠肉眼。

## 总结

这个项目最值钱的不是任何单个 API，而是几个**设计思想**：

1. **前景/背景分离** —— 边缘采样 + RANSAC 双重保险
2. **用滤波器残差定义"异常"** —— 比窗口方差更本质
3. **阈值与分辨率解耦** —— 让参数有物理意义
4. **算法与表现分离** —— `MotionAnalyzer` 只吃灰度图吐数据，CLI、GUI、无窗口批处理零成本复用

工具链：OpenCV（视觉）+ NumPy（计算）+ Tkinter（GUI）+ PyInstaller（分发），全部开源免费。
