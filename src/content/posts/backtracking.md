# 从二叉树递归到N皇后，彻底吃透回溯思想

> 本周的学习重心放在了算法题中最经典、也最容易让人“脑壳疼”的**递归与回溯**上。从LeetCode 104（二叉树的最大深度）的懵懂，到LeetCode 46（全排列）的纠结，再到洛谷 P1219（八皇后/跳棋棋盘）的超时与优化，我对“递归”的理解经历了一次彻底的蜕变。特此记录，希望能帮到同样卡在回溯入门阶段的同学。

## 一、 递归的起点：LeetCode 104. 二叉树的最大深度

这是我本周接触的第一道递归题。一开始，我完全不知道怎么写，甚至连 `if not root: return 0` 这种终止条件都觉得反直觉。

### 我的思维误区：
我总想试图在脑子里“跟踪”每一次递归的调用，结果发现栈太深，根本记不住。

### 豁然开朗的关键：
**不要去想全局，只看“当前这一个节点”发生了什么。**

代码极其简单，但蕴含了分治的思想：
```python
class Solution:
    def maxDepth(self, root: TreeNode | None) -> int:
        if not root: 
            return 0
        left_depth = self.maxDepth(root.left)
        right_depth = self.maxDepth(root.right)
        return max(left_depth, right_depth) + 1
```

**核心领悟：**
1. **`root` 为什么变成空？** 它不是“变成”了空，而是我们主动把空节点作为参数传进去了（比如叶子节点的子节点就是 `None`）。空节点的深度定义为 0，这就是递归的终止条件。
2. **递归如何计算深度？** 把左子树和右子树分别交给“另一个自己”去算，等它们把结果报上来，取最大值再加 1（当前节点自己这一层）。
3. **`+1` 的物理意义：** 左右子树算出来的深度是不包含当前节点的，所以最后必须加上当前节点自己。

## 二、 回溯的入门：LeetCode 46. 全排列

理解了二叉树递归后，我迎来了真正的挑战——全排列。这道题要求返回所有可能的排列。

### 我最初的错误思路：
我当时想的是：“设一个全局变量 N 记录拼了多少数组，递归终止条件设为 N 等于数组长度的阶乘”。结果发现，这根本没法写，因为递归不知道“下一步该选哪个数字”。

### 正确的打开方式：回溯（Backtracking）
全排列的本质，是**“带撤销操作的深度优先搜索”**。我们可以想象成手里有3张牌，往3个空位里放。

```python
class Solution:
    def permute(self, nums: list[int]) -> list[list[int]]:
        result = []
        path = []
        used = [False] * len(nums)

        def backtrack():
            if len(path) == len(nums):
                result.append(path.copy()) # 关键：必须copy！
                return

            for i in range(len(nums)):
                if used[i]: continue
                used[i] = True
                path.append(nums[i])
                backtrack()
                path.pop()          # 回溯：撤销选择
                used[i] = False     # 回溯：恢复状态

        backtrack()
        return result
```

**核心领悟：**
1. **`for` 循环和递归的关系：** `backtrack()` 并不是“函数结束后再调用”，而是在 `for` 循环**内部**每次迭代都调用一次。`for` 循环负责“尝试所有可能的分支”，递归负责“沿着当前分支深入探索”。
2. **为什么不能直接 `print(path)`？** 因为判题系统看的是函数的**返回值**（`return result`），而不是控制台打印的内容。
3. **`path.copy()` 的灵魂作用：** Python 中的列表是可变对象，直接 `append(path)` 存的是**引用（地址）**，后续 `pop` 操作会污染之前存进去的结果。`.copy()` 相当于“拍一张快照”，把当前瞬间的状态定格下来。

## 三、 回溯的进阶：洛谷 P1219 跳棋棋盘（N皇后问题）

这是本周最硬核的一道题，也是洛谷上经典的回溯题。题目要求在 \(n \times n\) 的棋盘上放 n 个棋子，使得每行、每列、每条对角线上至多有一个棋子。

### 初步思路：
这其实就是**“带条件限制的全排列”**。在每一行选一个列号，只要不重复（不同列），且不在同一对角线上即可。

### 遭遇超时（TLE）：
最开始写的时候，我在每一层递归里用一个 `for` 循环去检查之前放过的棋子有没有冲突。虽然思路是对的，但提交后发现**超时**。

**超时原因分析：**
每次判断当前位置合不合法，都要遍历之前所有的棋子，时间复杂度是 \(O(n)\)。当 \(n\) 变大时，这个检查动作被调用了成千上万次，累计耗时太高。

### 优化大招：空间换时间（哈希表优化）
我们可以开三个布尔数组，专门记录哪些列、哪些对角线被占用了。这样每次判断就是 **\(O(1)\)** 的时间复杂度。

**关键公式（对角线判定）：**
- **主对角线（左上到右下）：** `row - col` 是一个常数（加 `n` 防止负数下标，即 `row - col + n`）。
- **副对角线（右上到左下）：** `row + col` 是一个常数。

**优化后的代码骨架：**

```python
def solve_n_queens(n):
    result = []
    path = []
    
    # 三个布尔数组，O(1) 判断是否被占用
    cols = [False] * n
    diag1 = [False] * (2 * n)
    diag2 = [False] * (2 * n)

    def backtrack(row):
        if row == n:
            result.append(path.copy())
            return
        
        for col in range(n):
            d1 = row - col + n
            d2 = row + col
            
            if cols[col] or diag1[d1] or diag2[d2]:
                continue
            
            # 做选择（标记占用）
            path.append(col)
            cols[col] = diag1[d1] = diag2[d2] = True
            
            backtrack(row + 1)
            
            # 撤销选择（恢复占用状态）
            path.pop()
            cols[col] = diag1[d1] = diag2[d2] = False

    backtrack(0)
    return result
```

**核心领悟：**
1. **剪枝（Pruning）是回溯的灵魂：** 如果发现当前路径已经不可能产生合法解（比如列冲突、对角线冲突），立刻跳过，不要继续往下搜。这就是为什么需要 `continue`。
2. **数组代替 `for` 循环检查：** 这是本题从 TLE 到 AC 的关键。用三个布尔数组记录状态，用空间换时间，这是经典的算法优化思想。

## 四、 本周踩坑总结

1. **递归不要试图“跟踪”全局：** 只关注当前层的逻辑，把剩下的交给递归。
2. **回溯三步走：** 做选择 -> 递归 -> 撤销选择。缺一不可。
3. **`copy` 不是可选项，是必选项：** 涉及列表引用时，务必用 `.copy()` 或 `[:]`。
4. **超时先看检查逻辑：** 如果能用数组（哈希）把 \(O(n)\) 的检查降到 \(O(1)\)，一定要用。

## 五、 写在最后

这一周的学习让我明白，**回溯算法本质上就是一棵决策树的深度优先遍历**。我们在树上走每一步，都记录当前路径；如果发现此路不通，就退回到上一个分叉点，换一条路继续走。
