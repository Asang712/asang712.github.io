# 二分查找

# 从数组查找走向答案空间：二分算法的两种打开方式

> **摘要**：二分算法不仅仅是“在有序数组里找数字”。本文从最基础的二分查找出发，结合 LeetCode 和洛谷的四道经典题目，带你深入理解“二分答案”这一强大的算法思想，并总结出一套通用的解题模板。

## 引言：从“猜数字”说起

让我们先玩一个小游戏：
> 我心里想了一个 1 到 100 之间的数字。你可以猜一个数，我只会告诉你“大了”、“小了”或者“猜对了”。最少几次能猜到？

答案是 **7 次**。

因为每次猜测都能排除一半的可能性，\(2^7 = 128 > 100\)，所以 7 次足够。

这就是二分算法（Binary Search）的核心思想：**每次排除一半的可能性，时间复杂度为 O(log n)**。100 万个数据，最多只需 20 次比较。

但今天我想聊的，不仅仅是这个。二分的真正威力，在于它有两种截然不同的应用模式，很多人学了多年算法，依然分不清这两者的区别。

---

## 第一部分：普通二分查找——在有序数组里“找东西”

### 1.1 标准模板（LeetCode 704）

普通二分查找的适用条件非常明确：**数组必须是有序的**。

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = left + (right - left) // 2  # 防溢出写法
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
                
        return -1
```

**三个关键点**：
1. **循环条件**：`left <= right`（闭区间，有等号）
2. **mid 计算**：`left + (right - left) // 2`（防溢出，Python 中不必须但好习惯）
3. **边界收缩**：必须带 `+1` 或 `-1`，否则会死循环

### 1.2 进阶：寻找左侧边界（洛谷 P2249）

如果数组中有重复元素，而你需要找**第一个**出现的位置，标准模板就不够了。

关键在于：**找到目标后不能立即返回**，而是要用一个变量记录位置，并继续向左收缩。

```python
def search_left(nums, target):
    left, right = 0, len(nums) - 1
    ans = -1
    
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            ans = mid
            right = mid - 1  # ⭐ 继续向左寻找
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
            
    return ans
```

**实战小贴士**：在洛谷等 OJ 平台上，如果数据量达到 \(10^6\) 级别，使用 `input()` 一定会超时（TLE）。必须改用 `sys.stdin.read().split()` 一次性读取所有输入。

## 第二部分：二分答案——在单调空间里“找最优”

### 2.1 一个颠覆认知的问题

如果数组是**无序**的，还能二分吗？

答案是：**能！但二分的对象变了。**

普通二分查找，是在**数组的下标**上做二分，依赖的是数组的**有序性**。
二分答案，是在**答案的取值范围**上做二分，依赖的是答案空间的**单调性**。

### 2.2 案例一：吃香蕉（LeetCode 875，求最小值）

**题目**：珂珂有 n 堆香蕉，每小时可以吃 k 根。她要在 h 小时内吃完所有香蕉，求最小的 k。

**单调性分析**：速度 k 越大，耗时越短；k 越小，耗时越长。

**二分范围**：`[1, max(piles)]`

```python
def minEatingSpeed(piles, h):
    left, right = 1, max(piles)
    ans = right
    
    while left <= right:
        mid = left + (right - left) // 2
        # 计算以速度 mid 吃完所有香蕉需要的小时数
        hours = 0
        for j in piles:
            hours += (j + mid - 1) // mid  # 向上取整的整数写法
        if hours <= h:
            ans = mid
            right = mid - 1  # ⭐ 可行，往左试探更小的速度
        else:
            left = mid + 1   # 不可行，加速
            
    return ans
```

### 2.3 案例二：砍树（洛谷 P1873，求最大值）

**题目**：有 n 棵树，锯片高度为 H，可以得到所有树高于 H 的部分。要在得到至少 M 米木材的前提下，求最高的 H。

**单调性分析**：高度 H 越高，得到的木材越少；H 越低，得到的木材越多。

**二分范围**：`[0, max(lines)]`

```python
def maxHeight(lines, M):
    left, right = 0, max(lines)
    ans = 0
    
    while left <= right:
        mid = left + (right - left) // 2
        # 计算以高度 mid 砍树能得到的木材总量
        wood = 0
        for height in lines:
            if height > mid:
                wood += height - mid
        if wood >= M:
            ans = mid
            left = mid + 1   # ⭐ 可行，往右试探更高的高度
        else:
            right = mid - 1  # 不可行，降低高度
            
    return ans
```

### 2.4 对比总结：边界收缩方向的判断

这是初学者最容易搞反的地方。请牢记：

| 题目类型 | 求什么 | 可行时 | 不可行时 |
| :--- | :--- | :--- | :--- |
| 吃香蕉 | **最小**速度 | `right = mid - 1` | `left = mid + 1` |
| 砍树 | **最大**高度 | `left = mid + 1` | `right = mid - 1` |

**记忆口诀**：
> 求最小，可行就往左边缩；
> 求最大，可行就往右边扩。

## 第三部分：二分答案通用三步走模板

无论题目怎么变，二分答案都可以套用以下三步：

### 第一步：确定答案的上下界
*   吃香蕉：速度范围 `[1, max(piles)]`
*   砍树：高度范围 `[0, max(lines)]`

### 第二步：编写 `check(mid)` 函数
判断当前猜测 `mid` 是否可行：
*   吃香蕉：算总耗时，判断是否 ≤ h
*   砍树：算总木材，判断是否 ≥ M

### 第三步：确定边界收缩方向
*   求最小：可行时 `right = mid - 1`，同时记录 `ans = mid`
*   求最大：可行时 `left = mid + 1`，同时记录 `ans = mid`

## 第四部分：Python 避坑与提速指南

### 坑点一：浮点数陷阱

在吃香蕉的 `check` 函数中，计算“一堆香蕉需要几小时”时：

```python
# ❌ 错误写法：浮点除法，慢且精度丢失
hours += int(j / mid + 0.5)

# ✅ 正确写法：整数除法，快且精确
hours += (j + mid - 1) // mid
```

**记忆公式**：`a` 除以 `b` 的向上取整 = `(a + b - 1) // b`

### 坑点二：海量数据 I/O 超时

在洛谷等 OJ 平台上，当数据量达到 \(10^6\) 时，`input()` 会成为性能瓶颈。

```python
import sys

# ✅ 极速输入：一次性读取
input_data = sys.stdin.read().split()

# ✅ 极速输出：一次性写入
sys.stdout.write(" ".join(map(str, ans_list)) + "\n")
```

### 坑点三：死循环

二分查找最怕的就是死循环，根本原因往往是边界收缩漏掉了 `+1` 或 `-1`。

```python
# ❌ 死循环
right = mid

# ✅ 正确
right = mid - 1
```

## 总结：一句话概括两种二分

| 对比项 | 普通二分查找 | 二分答案 |
| :--- | :--- | :--- |
| **二分对象** | 数组的下标 | 答案的取值范围 |
| **依赖条件** | 数组有序 | 答案空间单调 |
| **原数组需要排序** | 必须 | 不需要 |
| **典型题目** | LC 704、P2249 | LC 875、P1873 |
| **核心代码** | `if nums[mid] == target` | `if check(mid)` |

**核心金句**：
> 普通二分查找，是在有序数组里“找东西”；
> 二分答案，是在单调空间里“找最优”。
